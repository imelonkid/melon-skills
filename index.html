工作原理：流程公开，事实私有

skill 只描述怎么做：步骤、检查项、红线。至于对谁做——哪台主机、什么 IP、面板在哪个端口——全部来自本机环境，公开仓库里一个都不写。

两个仓库的分工：

放在哪放什么不放什么
melon-skills（公开）通用流程、检查脚本、模板、红线IP、端口、面板入口、密钥、账号、个人信息
melon-ops（私有）主机事实、注册表、基线、手册、ops.zsh密码、AK/SK、面板安全入口（只在 1Password）
1PasswordSSH 私钥、云账号、ops.secrets.zsh 原件—

安装

git clone git@github.com:imelonkid/melon-skills.git ~/Workspace/melon-skills
~/Workspace/melon-skills/install.sh

install.sh 把 skills/* 逐个软链到 ~/.claude/skills/，并启用提交前的敏感信息扫描。可以重复执行。

运维电脑用 melon-ops/workstation/setup.sh 初始化时会自动克隆并安装本仓库，不用单独做。

本机是软链接。改 ~/.claude/skills/<名> 就是改本仓库，改完记得提交推送。

敏感信息防线

  1. 写的时候：只写变量名

    路径、主机、端口一律用 $VAR 引用；示例值用 __占位符__。

  2. 提交的时候：pre-commit 自动扫描

    scripts/scan-secrets.sh 检查公网 IP、私钥、云厂商 AK、各类 token、手机号、身份证号；还会把本机 ops.zsh 里的 IP、端口、面板入口的实际值当字面量去搜。命中就拒绝提交。

  3. 随时：全量扫描

    不带参数运行 scripts/scan-secrets.sh 扫全部已跟踪文件。确属误报的行，行尾加 scan:allow。

已经推上去了怎么办？公开仓库的历史可能已被抓取。先轮换泄露的密钥或改掉暴露的端口，再处理历史——顺序不能反。

维护约定

完整规则见仓库根目录的 AGENTS.md（CLAUDE.md 引用它）。最重要的一条：

改代码必须同步改文档。新增、改名、改流程、改依赖的环境变量时，同一个提交里要同时更新：SKILL.md、README.md 的清单、site/site.js 的清单、对应的 site/<skill>.html，以及本页受影响的段落。
