Hero 宣传页

维护与接入统一托管在私有仓库 imelonkid/melon-pages 的产品 Hero 宣传页：零额外容器进程、按域名路由、30 天静态资源版本化、三端响应式与下载校验 QA，以及 PR 审核后由门户人工发布的上线纪律。

melon-pages多站统一私有仓库
0 容器边缘 OpenResty 直出
64 MiB全站打包体积硬上限
PR → 门户不从本机或 Agent 直发

什么时候用

改 Hero 页更新官网 / 宣传页新增产品落地页维护 melon-pageshero page

只面向纯公开静态页面（HTML / CSS / JS / 图片），不包含后端接口、用户数据、登录态或密钥。主机坐标、证书路径与站点绝对目录运行时从私有运维仓库 $OPS_REPO 读取。

统一仓库与零进程路由

部分约定
site/<domain>/各产品独立目录，包含 index.html 与带版本号的 assets/
site/shared/跨站共享静态资源，经 Nginx alias 挂载，禁止软链接
site/index.html根目录索引页，page_artifact.py 与 check-hero.py 均强校验
sites.yaml结构化站点注册表：domain、routing_mode、assets_version、download_manifest 等
纯 Hero 域名由边缘 hero-pages.conf 的显式白名单 map $host 统一分发，未命中返回 404
混合 API + Hero 域名各自 <domain>.conf 保留 /v1/ 与 /health 后端转发，静态路由指向 <站点目录>/current/<domain>
版本探针两类配置均须精确匹配 location = /.page-release.json 并用 alias 指向 <站点目录>/current/.page-release.json（no-store）

打包约束与缓存规则

全站体积 ≤ 64 MiB

硬上限覆盖所有已接入站点总和；CI 预警线 < 60 MiB，图片按展示尺寸压缩。

静态资源版本化

/index.html 不缓存，/assets/ 缓存 30 天；改过的 CSS / JS / 图片必须升文件名版本号（如 hero-v1.css → hero-v2.css）。

零软链接与点文件防护

site/ 下禁止 symlink、.. 与已提交的 .page-release.json；边缘规则屏蔽隐藏文件。

无 GitHub SSH 凭据

release-page.yml 调用 page-release@v2 仅传 OSS 制品，部署由内网受限程序拉取切换。

QA 清单与发布纪律

  1. 三端响应式实测

    在桌面 1280px、平板 728px、手机 390px 下检查：无横向溢出、无控制台报错、图片完整无裁切、交互正常。

  2. 多语言与下载校验

    中英切换（ZH/EN）完整无残留；下载链接用 new URL() 严格校验登记的 HTTPS OSS 前缀与 .dmg 后缀，拒绝凭据、query 与 hash。

  3. 合规页脚

    保留 ICP 备案号 京ICP备16017845号-2 与 Made by melonkid ↗ 署名。

  4. 首次建仓一次性配置

    仅在首次初始化 imelonkid/melon-pages（或新建独立 Hero 仓库）时执行一次：运行 github-apply.sh --kind desktop 开启分支保护与 4 项 CI 检查，复用 melon-download 桶配置最小权限前缀，先用 macos-desktop-launch/scripts/verify.py oss --write-test 实测 PUT 写入与匿名回读通过，再通过 gh variable set / gh secret set 写入 production 环境的 OSS_BUCKET、OSS_ENDPOINT 与两个 OSS_ACCESS_KEY_* 密钥；后续新增子站无需重复。

  5. PR 审阅与门户发版

    跑通 bash scripts/ci-test.sh 与 gitleaks git . --redact 后提 PR 到 main；Agent 不推发布 tag、不 SSH 部署，由用户合并后在内网门户按 patch / minor / major 手动发布。
