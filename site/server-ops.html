事实从哪来

什么在哪
主机别名、IP、面板端口、容器基线环境变量，定义在 ~/.zsh/conf.d/ops.zsh（私有仓库的软链）
规范、站点规划、主机档案、手册、踩坑记录$OPS_REPO/docs/，入口是白皮书 whitepaper.html
服务清单、站点、主机基线$OPS_REPO/registry/
面板安全入口等敏感值本机 ops.secrets.zsh，原件在 1Password

站点用前缀描述：OPS_SITES="ALI TX JD"，每个前缀 P 有 P_SSH、P_IP，可选 P_CONTAINERS、P_PANEL_PORT。加一朵云 = 在 ops.zsh 加一个前缀，脚本不用改。

私有仓库不在本机？说明这台电脑还没初始化运维终端。skill 会停下来让你先按 melon-ops/workstation/README.md 初始化，不会凭记忆操作服务器。

巡检脚本（全部只读）

$SKILLS_REPO/skills/server-ops/scripts/status.sh
$SKILLS_REPO/skills/server-ops/scripts/audit.sh [--sudo]
$OPS_REPO/baseline/check.py --quiet
脚本看什么
status.sh每台主机的资源、内核、运行时长；容器健康状态；与 P_CONTAINERS 对比的漂移；运维中心 Gatus 的探活汇总
audit.sh从本机探测面板和监控端口没有暴露在公网；sshd 生效值（禁密码、仅密钥、MaxAuthTries）；待打安全补丁；容器自启策略；磁盘；运维基线
check.py每台主机对照 registry/baseline.toml：系统、软件、SSH、Docker、内网

缺环境变量时脚本直接说缺哪个，不猜默认值。

怎么改主机

  1. 一律走基线

    $OPS_REPO/baseline/apply.py <主机> <步骤>。sudo 要密码的主机，脚本只把命令准备好，交给用户执行——这是刻意保留的人工关卡。

  2. 重点业务机分段改

    先做低风险、不重启的 → 复核 → 再动存储或内核 → 用户确认后手动重启。

  3. 重建业务容器以注册表为准

    用服务清单里的 deploy.up，不凭印象拼命令。

  4. 改完复核

    check.py <主机> 全绿才算完成。

写回规则

  • 改机器先改 $OPS_REPO/registry/，再改 docs/，在私有仓库提交推送；
  • 新踩的坑追加到 05-gotchas.md，注明日期；
  • 容器增减：同步改 ops.zsh 的 P_CONTAINERS；
  • 主机事实只进私有仓库，绝不写进本 skill。

红线

这些没有例外。每一条背后都是真实损失或险些发生的损失。
  1. 管理面板绝不对公网开放。1Panel / Beszel / Gatus 只走 SSH 隧道或 WireGuard。
  2. 改 sshd 按固定顺序：快照 → 确认 VNC → 旧会话不关 → sshd -t → sshd -T → reload → 新窗口验证 → 再关旧会话。
  3. root 密码不能删。VNC 是不依赖 SSH 的唯一救援通道。
  4. 1Panel 托管的容器从面板卸载，直接 docker rm 会留残留。
  5. 删东西前先停用观察几天。
  6. 安全组规则写描述和日期。
  7. 隧道端口和服务端口别搞混。
  8. 重点业务的数据库变更先备份、先确认。
  9. 有状态服务不多站点同时写，切主备由第三站点裁判。
  10. 线上内容可能不在 git 里，别从干净 checkout 做 rsync --delete。
  11. 密码、验证码、证件只由用户本人输入。
