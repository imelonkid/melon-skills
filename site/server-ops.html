巡检脚本

全部只读。缺环境变量时直接说缺哪个，不猜默认值。

全景：主机 + 容器 + 探活 + 漂移
$SKILLS_REPO/skills/server-ops/scripts/status.sh
安全核查 + 运维基线
$SKILLS_REPO/skills/server-ops/scripts/audit.sh [--sudo]
脚本看什么
status.sh每台主机的资源、内核、运行时长；容器健康状态；与 P_CONTAINERS 对比的漂移；运维中心 Gatus 探活汇总
audit.sh从本机探测面板和监控端口没有暴露在公网；sshd 生效值；待打安全补丁；容器自启策略；磁盘；运维基线
$OPS_REPO/baseline/check.py每台主机对照 registry/baseline.toml：系统、软件、SSH、Docker、内网

怎么改主机

  1. 一律走基线 Claude

    $OPS_REPO/baseline/apply.py <主机> <步骤>

  2. sudo 要密码的主机 用户

    脚本只把命令准备好，交给用户执行——刻意保留的人工关卡。

  3. 重点业务机分段改

    先做低风险、不重启的 → 复核 → 再动存储或内核 → 用户确认后手动重启。

  4. 业务发布与回滚只经部署入口

    日常在 GitHub Actions 点「发布 / 回滚」，应急用项目的 scripts/deploy.sh，两条路都只经主机上的 deploy-agent（deploy 用户 + 强制命令，没有 shell）。线上版本：ssh <主机>-deploy status <服务>。不在服务器上手改镜像或 compose。

  5. 重建业务容器以注册表为准

    用服务清单里的 deploy.up，不凭印象拼命令。

  6. 复核

    check.py <主机> 全绿才算完成。

红线

⛔

这些没有例外。每一条背后都是真实损失或险些发生的损失。

1 · 面板绝不对公网开放

1Panel / Beszel / Gatus 只走 SSH 隧道或 WireGuard。

2 · 改 sshd 按固定顺序

快照 → 确认 VNC → 旧会话不关 → sshd -t → sshd -T → reload → 新窗口验证 → 再关旧会话。

3 · root 密码不能删

VNC 是不依赖 SSH 的唯一救援通道。

4 · 1Panel 的容器从面板卸载

直接 docker rm 会留残留。

5 · 删之前先停用观察

docker stop + --restart no，几天后再删。

6 · 安全组写描述和日期

否则半年后没人知道它为什么存在。

7 · 隧道端口 ≠ 服务端口

改了转发要 panel stop 重开。

8 · 重点业务先备份再动

数据库变更先 mysqldump --single-transaction，再确认。

9 · 有状态服务不多点写

切主备先隔离旧主，由第三站点裁判。

10 · 线上内容可能不在 git

别从干净 checkout 做 rsync --delete。

11 · 密码只由用户本人输入

sudo 密码、验证码、证件都交给用户。
