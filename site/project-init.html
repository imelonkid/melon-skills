硬性要求

必须托管到 GitHub §5.1

不用跑在业务服务器上的自建托管；构建依赖的兄弟仓库同样要在 GitHub。

服务器挂了，代码和数据会一起没。

先有 .gitignore 再提交 §5.4

.env、data/、数据库文件、私钥一律不进 git。

进了历史就很难清干净。

服务必须注册 §9.1

不在 registry/services/ 里的服务不允许上线。

备份、探活、灾备都从注册表生成。

版本可追溯 §5.1

分支 main；发布打 v* 标签；镜像标签取 git describe。

出事时知道线上跑的是哪一版。
ℹ️

新仓库默认私有，用户明确说公开才公开。鸿蒙项目：仓库里的 build-profile.json5 是 "signingConfigs": []，本机签名用 git update-index --skip-worktree 留在本机。

自动定级

只问推不出来的（项目名、类型、技术栈、可见性、域名）；其余由 Claude 按规范推出，写进确认摘要，用户可改。

项怎么推
数据等级 §2有用户数据（账号、订单、消息、对话）→ T0；上传媒体、业务配置 → T1；可重建 → T2。取所有资产里最高的
灾备等级 §3T0 有状态 → L2 温备 + 持续复制；T1 → L1；无状态 → L3
主站点只放 roles 含 compute 的站点；写着某业务「专用」的不放别的项目；运维中心 / 温备站点不放新业务
备站点与裁判直接取 standby_pairs 中 primary = 主站点那一条，不自己发明
ICP §4.7主、备站点 icp_access 都是 true 才能对外；pending 写进 known_gaps
数据库默认 SQLite（WAL），单文件放 data/，能直接上 Litestream 做 L2；确需 MySQL / Postgres 用只读账号导出、binlog / WAL 复制

流程

  1. 读规范 Claude

    上表五份文件；$OPS_REPO 不在就只做 git 和骨架，交付时说明未注册。

  2. 问清楚并定级 Claude

    一次问完；定级结果给用户确认。

  3. 目录与 git Claude

    默认 ~/Workspace/<名>。已有项目 = 纳管模式：先跑 check.sh 拿差距清单，保留历史只补缺的。

  4. 生成骨架 Claude

    README（含上线准入清单）、CLAUDE.md；服务另加 Dockerfile、compose、.env.example、部署脚本、/health。

  5. 首次提交、扫描、推送 Claude

    先提交，再用 gitleaks git 扫 git 历史，命中都确认是误报才推送。历史里有密钥：没推过的先备份再 filter-repo 清理；推过的先轮换密钥。

    gh repo create imelonkid/<名> --private --source . --remote origin --push

  6. 注册 Claude

    在 ops 仓库写 registry/services/<名>.yaml，状态 building；做不到的写 known_gaps，纳管项目的大缺口同时进路线图差距表。推不推送问用户。

  7. 检查 Claude

    scripts/check.sh：✗ 必须修，△ 写进 README「上线准入」。

  8. 交付 用户

    1Password 条目、服务器目录、ICP / DNS / 证书——见「交给用户的事」。

容器规范

要求为什么
mem_limit · healthcheck · restart: unless-stopped §5.6一个服务吃满内存不能拖垮整台机器；挂了能被发现、能自己起来
端口只绑 127.0.0.1 §6.5对外统一走反向代理 + HTTPS，不开新的安全组端口
数据只在 ./data/ §5.5备份任务按注册表 assets 从这里取
服务内 env_file: .env--env-file 插值不进容器标签，灾备重建时会漏（真实踩过）
不写 logging: §6日志轮转由主机基线统一配置
第三方镜像钉版本不用 latest，重建时拿到的就是测过的那一版
对象存储用 S3 兼容接口 §5.8主云出事时能切到另一朵云的副本
SQLite 备份只用 sqlite3 .backup §7WAL 模式下直接 cp 会拿到不一致的文件

可观测

规范 §8。运维中心的 Collector 还没上线也先按这个写，到时只需填一个地址。

项约定
日志JSON 到 stdout，带 trace_id；密码、token、手机号必须脱敏
埋点OpenTelemetry SDK；OTEL_SERVICE_NAME、OTEL_RESOURCE_ATTRIBUTES（版本、环境、云厂商）由 compose 注入
导出OTEL_EXPORTER_OTLP_ENDPOINT 为空 = 不导出；采样在 Collector 做，代码不写死
业务指标<服务>_<领域>_<事件>_total；标签禁止 user_id、URL 原文等高基数值
探活注册表 endpoints.url 写公网域名的 /health：顺带验 DNS、证书、反代

发布与回滚：一律走 tag

线上版本永远等于某个 git tag。发新版 = 打一个新 tag；回滚 = 上线一个旧 tag。没有 tag 的代码不上线。

发新版（minor / major 同理）
scripts/deploy.sh patch
回滚到上一个成功上线的版本
scripts/deploy.sh rollback
上线 / 回滚到指定 tag
scripts/deploy.sh v1.2.0
线上版本与最近部署事件
scripts/deploy.sh status

发新版的流程

08–23 点窗口→HEAD 干净且已推到 main→打 vX.Y.Z 并推到 GitHub→git archive 从 tag 构建→镜像 + compose 传到服务器→T0 先备份→切到 :prod→/health 60 秒→不过自动切回上一版
规则说明 §5.1 · §9.3
tag 先上 GitHub新 tag 只打在已推送的干净 HEAD 上，推到 GitHub 后才构建；线上版本永远能在仓库里找到
从 tag 构建镜像和 compose 都取自 tag 的内容，与本地工作区无关；版本号经 build-arg 烘进镜像 APP_VERSION
秒级回滚服务器保留最近 5 个版本的镜像和 compose（releases/<tag>.yml），回滚不用重新构建
可审计RELEASE 记当前版本；deploy.log 记时间、tag、类型（release / rollback / redeploy / auto-rollback）、操作人、结果
变更窗口发新版只在 08–23 点，窗口外 EMERGENCY=1 并 24 小时内补复盘；回滚不受限
可回滚的迁移数据库迁移必须向后兼容（先扩展、再收缩），回滚到上一个 tag 仍能跑
不手改线上不在服务器上手动改镜像标签、compose 或 docker run，否则版本记录就不可信

检查脚本

~/.claude/skills/project-init/scripts/check.sh <项目目录>
类别检查项
git是仓库、分支 main、远端在 GitHub、已推送、没有跟踪密钥或数据文件、.gitignore 覆盖 .env；鸿蒙 build-profile.json5 不含签名密码；gitleaks 扫 git 历史
文件README、CLAUDE.md；服务另查 .env.example（含 OTel）、Dockerfile 烘入 APP_VERSION、/health
发布deploy.sh 按 tag 发布（从 tag 构建）、支持 rollback、有发布窗口、健康检查失败自动回滚
composemem_limit / healthcheck / restart；端口只绑本机；env_file；数据挂载；没有 logging:；第三方镜像钉版本；没用厂商专有存储 SDK
注册表已登记；必填字段齐全；code.repo 是 GitHub；没有 TODO / 占位符；L2 的主·备·裁判与 standby_pairs 一致，裁判是第三站点

交给用户的事

  1. 1Password 条目 用户

    创建 ops/<名>/prod，填真实配置。Claude 不经手密钥值。

  2. 服务器目录 用户

    /opt/<名>/data；sudo 要密码的主机由用户执行。

  3. 域名 用户

    主、备站点 ICP 接入；DNS TTL ≤ 300；反向代理与证书。

  4. 上线准入 Claude

    用 server-ops：首次备份 + 恢复验证、备份心跳、Gatus 探活与告警实测、panel 索引、主机档案、注册表改 active。

⛔

初始化阶段不会做：ssh 服务器、改安全组和 DNS；替用户在 1Password 或云控制台录入；push --force 或改已有项目的历史；没说公开就建公开仓库；帮没注册的服务上线。
