阿里云 OSS 工具

为桌面端安装包、Hero 静态页制品及业务存储提供统一的阿里云 OSS 最小权限配置指导与校验脚本：生成策略模板、核对 RAM 与 Bucket Policy、实测目标前缀 PUT 写入与匿名 GET 回读、检查 GitHub 环境与排查 403。

最小权限仅目标前缀 PutObject
PUT + GET先实测通畅再发版
隐藏输入密钥不进终端历史
统一复用桌面端与 Hero 共用

什么时候用

建 OSS 子账号配 OSS 权限校验 OSS 读写排查 OSS 403阿里云 OSS 工具

每次为新项目建立 OSS 写入前缀、修改 RAM / Bucket Policy 权限、或首次门户发版撞 403 排障时使用。macos-desktop-launch 与 hero-pages 均直接复用本技能的流程与脚本。

统一校验脚本（oss_verify.py）

子命令默认权限用途
render-policy只读按主账号 UID、地域、桶名与前缀输出最小权限 RAM 写策略与 Bucket 匿名读参考 JSON
policy只读静态核对导出的 RAM 自定义策略与 Bucket Policy 是否准确覆盖目标前缀
probe --write-test写入测试文件隐藏输入 AccessKey，向 <前缀>/ci-test.txt 写入随机内容并匿名 GET 逐字节回读（私有前缀可加 --skip-read）
env只读核对 GitHub production 环境的 OSS_BUCKET / OSS_ENDPOINT 值及密钥名称是否配齐

标准接入与验证流程

  1. 生成最小权限策略

    运行 oss_verify.py render-policy 生成仅允许 oss:PutObject 于目标 <桶>/<前缀>/* 的自定义策略（不给删除与列桶权限），确认使用主账号数字 UID 与 oss-cn-* 地域段。

  2. 创建 RAM 子账号并配置 Bucket 读权限

    创建仅开放 OpenAPI AccessKey 的子账号并附加该策略，将凭据存入 1Password；若该前缀需要公开下载或边缘拉包，在 Bucket Policy 中新增该前缀的匿名 oss:GetObject（保留其他规则）。

  3. 先实测读写通畅

    运行 oss_verify.py probe --write-test 确认本次 PUT 200 与匿名 GET 200 逐字节匹配，再写入 GitHub production 变量与密钥，避免正式发版阶段撞 403。
