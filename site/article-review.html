SKILL · ARTICLE-REVIEW

文章审阅

博客「朝花夕拾」发布前的必经一步：查错别字、语病、文笔、标签和图片。只审上次发布以来改过的文章，产出一个待审 commit 和逐字对比的 diff 页面，作者点头才发布。

6类检查
增量只审上次发布以来的改动
逐字diff 页面高亮到字符
必经没审过的文章发不出去

两条铁律

笔记是唯一事实来源

线上文章由 Obsidian 笔记同步生成，博客仓库的 src/content/posts/ 是产物。要改内容，永远先改笔记再同步。

否则下次同步就被覆盖，笔记和线上悄悄分叉。

改动先落成待审 commit

审阅的产出是建议，采不采纳是作者的事。

diff 比在对话里复述准确得多。

审哪几篇

每次成功上线后，笔记仓库自动打 pub/YYYYMMDD-N 标签。

最新的 pub 标签→现在（含未提交改动）=本次审阅范围

博客仓库里的 review-scan.mjs 按正文哈希比对，已审且没改过的自动跳过；输出「没有需要审阅的文章」时如实说，不硬找活干。

审什么

类别重点
错别字的 / 地 / 得、在 / 再、做 / 作、需 / 须……；技术名词大小写（GitHub、JavaScript、MySQL）
语病成分残缺、搭配不当、啰嗦、语序、中英文之间的空格与标点
文笔与风格克制、具体、有人味：具体物优先于抽象概括；技术文也要有人；去掉 AI 腔；长短句交错；结尾收束而不拔高
frontmatterdate 是发表日，上线后不改；updated 自动写；publish / draft / slug / excerpt
标签 硬卡控视觉宽度 ≤ 8、必须在白名单里；默认不新增，优先用现有标签覆盖
图片 必查跑同步与发布前检查确认没有断链；配图要有说明；截图里不能露内部信息

每条问题都给原文和改法；没问题的篇目也要明说「未见明显问题」。

审完之后

  1. 先给报告 Claude

    按篇列出问题。

  2. 决定采纳哪些 作者

    风格建议是建议，拒绝就不坚持。

  3. 确认笔记仓库干净 Claude

    作者自己的改动和审阅建议不混在同一个 commit 里。

  4. 改笔记，提交待审 commit Claude

    消息里写清改了什么、为什么。

  5. 发逐字 diff 页面 Claude

    中文改几个字，git diff 会整行标红；这个页面只高亮真正变动的字符。

  6. 记录审阅状态 Claude

    review-scan.mjs --mark；已上线文章正文变了会自动写 updated。

  7. 点头后发布 作者

    发布成功才打 pub/ 标签，失败不打，避免下次漏审。
